# fix-1 책 집기·운반 실패 분석

> **핵심 판단:** 책을 들어 올리는 동작은 학습했지만, **직접 만든 잡기를 유지하며 한 손 회전·운반으로 연결하는 과정**이 불안정하다.
>
> 먼저 확인할 것은 “더 학습해야 하는가?”가 아니라 **“실제 잡기가 정지 상태에서도 유지되는가, 움직일 때만 무너지는가?”**이다.

## 1. 분석 대상

| 항목 | 기준 |
|---|---|
| 과제 | 책 `place_book` — 컵 과제가 아님 |
| 버전 | 공식 `environment_iteration/iterations/fix-1` |
| 코드 기준 | `47921ff40c` 및 학습 당시 `44135d8` |
| 주요 비교 | 같은 fix-1의 epoch 3,000과 epoch 15,260 |
| 수행 범위 | 코드·문서·기존 평가·영상 요약 확인. 수정·학습·시뮬레이션 실행 없음 |

**fix-1은 수정 항목 1번이 아니라 아래 변경을 묶은 환경 전체다.**

- 책상 충돌 형상을 실제 윗면에 맞춘 상자로 변경.
- 책 충돌 형상을 단순화하고 질량을 약 7.1kg에서 1kg으로 변경.
- history encoder 입력 배열 오류 수정.
- 현재 동작 진행 시점인 phase를 관측에 추가.
- 학습 중 책이 참조 위치에서 25cm 넘게 벗어나면 episode 종료.

이 변경들은 초기 배치·과도한 질량·입력 오류를 개선했다. **안정적인 한 손 잡기와 운반까지 보장한 것은 아니다.** 개별 변경 효과는 분리 실험이 없어 확정할 수 없다. [버전 정의 및 변경 내역][version]

## 2. 실패는 두 종류로 나눠야 한다

조건별 96개 episode의 확률적 정책 평가다. 아래 `t`는 reset 이후 제어 step이며, 참조 데이터의 프레임 번호와 다르다.

| 구분 | e3000 | e15260 |
|---|---|---|
| lift 성공 | 46.9% | 99.0% |
| 전체 과제 성공 | 0% — 95% 신뢰구간 0–4% | 0% — 95% 신뢰구간 0–4% |
| 시연 구간 내 넘어짐 | 95.8% | 12.5% |
| 최초 평가 실패 | 주로 t65–68, 상승 지연·경로 이탈 | 주로 t72, 경로 이탈 |
| 이후 물리적 실패 | 운반 전환에서 몸이 무너지며 책을 놓침 | 몸이 서 있는 동안 책을 놓침, 낙하 중앙 t87 |
| 핵심 병목 | **제때 들어 올려 운반 상태로 진입하기** | **들어 올린 책의 회전·한 손 잡기 유지하기** |

e3000에서는 t70의 책 높이가 **0.80m**, 참조는 **0.99m**다. 운반 전에 이미 뒤처진다. e15260에서는 같은 시점의 높이가 **0.96m**로 개선되지만, 이후 책을 놓친다. [e3000 결과][result3000] · [e15260 결과][result15260]

**주의할 해석**

- `lift 성공`은 안정적인 운반 성공이 아니다.
- 보고서의 `grasp`는 손목 거리와 책 높이를 이용한 추정이다. 책 한쪽이 책상에 기대 선 상태도 포함할 수 있다.
- 전체 성공 기준은 시연 구간 내내 책 위치 오차 10cm 이하이며 넘어지지 않는 것이다. **평가 기준 이탈과 실제 낙하는 구분**해야 한다. [지표 코드][metrics]

## 3. 원인 후보 — 우선순위 3개

### ① 한 손 잡기의 접촉·회전 안정성

**확인된 사실**

- 시연에서는 오른손이 먼저 떠나고 왼손이 책 가장자리를 집어 운반한다.
- 참조 잡기 자세를 유지하는 probe에서 fix-1은 **0/56** 유지였다.
- 후속 진단에서 fix-1 e3000 정책에 강한 solver와 기존 접촉 거리를 적용하자, 평균 유지 시간이 **10.0 → 25.5프레임**, 낙하 비율이 **55% → 21%**로 변했다. 이 수치는 원래 fix-1의 공식 결과가 아니라 **환경을 바꾼 후속 진단**이다. [잡기 진단][version] · [후속 비교][followup]

**해석 — 근거가 강함**

책을 위로 올릴 정도의 접촉은 만들지만, 한 손으로 회전하는 책을 지탱할 만큼 안정적이지 않을 수 있다.

**아직 모르는 것**

정책이 먼저 손을 여는지, 닫힌 손 안에서 책이 먼저 미끄러지는지는 현재 기록만으로 확정할 수 없다. `0/56`도 시험한 참조 자세·PD·solver 조합의 결과이며, 모든 잡기가 불가능하다는 뜻은 아니다.

### ② 직접 집은 상태와 학습에서 주어진 운반 상태의 차이

**확인된 사실**

후속 진단에서 **fix-1 e3000도** 책을 참조 중간 자세에 배치해 시작하면 60프레임 동안 참조 위치에서 25cm 이내를 유지하는 결과가 나왔다. 책이 아직 책상 위에 있는 시점에서 시작하면 pickup에 실패했다. [중간 시작 비교][followup]

**해석 — e3000에서 근거가 강함**

정책이 다음 두 상태를 다르게 처리할 가능성이 크다.

| 학습에서 주어지는 상태 | 직접 집어서 도달한 상태 |
|---|---|
| 참조에 가까운 책·손·몸 자세 | 늦게 올라온 책, 다른 방향과 잡기 위치 |
| 참조 이력으로 초기화 | 실제 집기 중 누적된 오차와 이력 |
| 운반을 시작하기 좋은 상태 | 잡기를 안정시키기 전에 운반 시점에 도달 |

**아직 모르는 것**

차이를 만드는 핵심이 잡기 위치인지, 몸의 균형·속도인지, history 입력인지 분리되지 않았다. 또한 **25cm·60프레임 유지**는 원래의 **10cm·전체 구간 성공**보다 느슨하다.

### ③ 학습 신호와 시작 프레임 샘플링

**확인된 사실**

- 물체 방향·선속도·각속도를 직접 맞추는 보상 계수가 0이다.
- 접촉 그래프 보상은 꺼져 있다. 다만 몸–물체 상대 위치 보상은 존재한다.
- 학습 episode는 60프레임이며, 물체 위치 오차가 25cm를 넘으면 종료한다. [설정][env] · [보상 코드][reward]

**추가 발견: ATS 연결 누락 의심**

어려운 시작 시점을 더 자주 뽑는 ATS 옵션이 있어도, 실제 시간 샘플러 생성 시 `reweight` 활성화 값이 전달되지 않는다. 기본값은 `False`이므로 **정적 코드상 균등 샘플링 분기**를 탄다. 학습 당시 코드에도 같은 경로가 있다. [호출부][ats-call] · [샘플러][ats-sampler]

**해석 — 원인 기여도는 미검증**

회전·접촉 안정성을 직접 유도하는 신호가 약하고, 어려운 집기 구간을 의도대로 집중 학습하지 않았을 가능성이 있다. 하지만 이 문제만으로 실패를 설명할 수는 없다. 기존 구조에서도 lift는 99%까지 개선됐다.

## 4. 지금 단정하면 안 되는 것

| 주장 | 현재 근거로 가능한 판단 |
|---|---|
| “운반 능력이 전혀 없다” | 중간 상태에서 시작하면 부분적으로 유지한다. |
| “마찰이나 질량만 바꾸면 된다” | 후속 probe에서 단독 변경으로 해결되지 않았다. |
| “관절 힘이 부족하다” | 실제 토크·제한 도달 여부가 없어 미확정이다. |
| “촉각 관측이 없다” | 손끝 접촉력은 들어간다. 다만 책·책상·자기 충돌을 구분하는 정보는 아니다. |
| “접촉 거리를 줄이면 좋아진다” | 기존 집기가 사라진 후속 결과가 있다. solver 개선과 별도로 비교해야 한다. |
| “더 오래 학습하면 해결된다” | lift와 균형은 개선됐지만 운반 낙하는 남았다. |

## 5. 다음 실험은 하나부터

### 우선: e15260이 직접 만든 잡기의 정지 유지 / 운반 비교

**선정 이유:** lift 성공이 99%여서 실제 정책이 만든 잡기를 얻기 쉽고, 현재 남은 낙하 원인을 직접 확인할 수 있다.

| 조건 | 방법 | 확인할 질문 |
|---|---|---|
| A — 정지 유지 | 실제 lift 직후 상태에서 목표 자세를 유지하는 진단 제어로 전환 | 움직이지 않아도 책이 빠지는가? |
| B — 운반 | 같은 방식으로 얻은 상태에서 기록된 운반 목표를 재생 | 움직이거나 회전할 때만 빠지는가? |

**공통으로 기록할 값**

1. 손 좌표계에서 본 책의 상대 위치·회전과 그 변화 속도.
2. 손가락 목표 각도와 실제 각도.
3. 손·책 접촉력, 책 높이, 낙하 시점.

**결과별 다음 행동**

| 관측 결과 | 우선 검토할 대상 |
|---|---|
| 정지 상태에서도 미끄러짐 | 잡기 형상·접촉 solver·참조 자세 정합성 |
| 정지는 유지되지만 운반에서 이탈 | 회전·가속도 부하, 동적 PD 추종 |
| 손을 여는 명령이 미끄러짐보다 먼저 발생 | 정책의 잡기→운반 전환 |
| 명령은 유지되는데 실제 손가락이 뒤처짐 | PD 설정·실제 토크 제한 |

이 실험은 **제어 개입을 포함한 물리 진단**이며 원래 과제 성공 평가가 아니다. A/B에서 solver·모델·제어 방식은 고정하고 목표의 시간 변화만 비교한다. 정지 전환의 급감속과 몸통 고정 여부도 통제해야 한다.

GPU 물리는 동일 상태를 복원해도 완전히 같은 결과를 보장하지 않는다. 반복 분포와 개입 직전 상태 차이를 확인해야 한다. 기존 도구에는 참조 자세 유지와 중간 시작 실험이 있지만, **실제 집기 상태에서의 A/B와 관절 목표 기록은 추가 계측이 필요하다. 이번에는 구현·실행하지 않았다.**

## 6. 수정은 진단 뒤에 하나씩

1. **접촉 문제라면:** 기존 접촉 거리를 유지한 채 solver 변수를 하나씩 비교한다.
2. **직접 집기 이후 상태만 문제라면:** 실제 pickup 종료 상태에서 운반을 학습하는 조건을 따로 비교한다.
3. **학습 신호 문제라면:** 물리 설정을 고정하고 보상 항 또는 샘플링 연결을 각각 별도 실험으로 바꾼다.

ATS는 먼저 런타임의 활성화 값과 실제 시작 프레임 분포를 확인한다. 보상·물리·초기화를 한꺼번에 바꾸면 무엇이 효과가 있었는지 알 수 없다.
