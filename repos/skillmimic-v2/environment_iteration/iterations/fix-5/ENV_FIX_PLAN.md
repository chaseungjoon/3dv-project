# 발의 이동과 한 손 잡기를 함께 보는 후속 실험 계획

**작성일:** 2026-11-20  
**기준:** `3dv-project@beabf95a17837806a55813c896c4838b40218a25`, fix-4 / epoch 3000  
**범위:** 코드·시연 설명·기존 평가를 바탕으로 한 실험 설계. 새 구현·시뮬레이션·학습은 실행하지 않았다.

## 핵심 제안

> **“발이 움직이는가”보다 “책을 유지하면서 지지를 바꾸고 몸을 실제로 옮기는가”를 측정해야 한다. 한 손 잡기는 시연의 원래 동작이므로 바로 양손으로 바꾸기보다, 한 손 전환·책의 하중·보행 시작을 분리해서 시험한다.**

추천 순서는 다음과 같다.

1. **발·몸·책·양손을 같은 시간축에서 계측한다.**
2. **실제 집기 후 상태와 참조 운반 상태를 비교한다.**
3. **책의 유효 하중만 줄여 보행이 회복되는지 진단한다.**
4. **필요하면 오른손 보조를 첫 보행 전환까지 유지하는 조건을 따로 시험한다.**
5. 결과에 맞춰 연결 학습·보조를 줄이는 학습·발 제어 중 **하나만** 변경한다.

이 문서는 [기존 후속 실험 계획](NEXT_EXPERIMENT_PLAN_2026-11-20.md)을 **보행과 잡기의 상호작용** 중심으로 구체화한 것이다.

## 1. 먼저 구분해야 할 사실

### 한 손으로 드는 것 자체는 오류가 아니다

저장소의 참조 분석에 따르면, 시연은 오른손을 책에서 떼고 **왼손 한 손으로 운반**한다. 오른손 이탈은 참조 프레임 약 62–65로 기록돼 있다. 따라서 한 손 사용을 보고 “양손 잡기 학습이 빠졌다”고 판단하면 과제를 잘못 해석할 수 있다. [참조 동작 설명][reference]

fix-4에서도 t100에 왼손목이 책 가까이에 있는 비율이 98%이고, 오른손목은 멀어진 것으로 기록된다. 다만 손목 근접은 실제 손가락의 지지력이나 시연과 동일한 접촉 구성을 증명하지 않는다. [fix-4 분석][iteration]

**검증해야 할 것은 다음 세 가지다.**

- 오른손을 떼는 **시점**이 현재 잡기와 몸 자세에 적합한가?
- 왼손의 실제 잡기가 **정지와 보행 중 하중을 버틸 수 있는가?**
- 책을 옆으로 뻗어 든 상태에서 **발의 지지 전환과 몸 이동을 시작할 수 있는가?**

### 발의 움직임과 실제 이동도 다르다

현재 기록에서 fix-4의 root 수평 이동은 시연 끝까지 약 0.26m, 참조는 약 1.1m다. 낮고 넓은 자세로 책을 유지하다가 떨어뜨린다. 이는 이동량 부족의 증거지만, **발이 완전히 멈췄는지, 제자리에서 움직이는지, 미끄러지는지**까지 확정하지는 못한다. [추가 trace 분석][iteration]

| 발에서 보일 수 있는 현상 | 의미 | 먼저 볼 것 |
|---|---|---|
| 두 발을 넓게 둔 채 거의 떼지 않음 | 지지 전환 시작 실패 가능성 | 좌우 하중 변화, 골반 위치, 다리 목표 |
| 발은 들었다 놓지만 몸은 거의 제자리 | 유효한 보폭·체중 이동 부족 가능성 | 착지 위치, root 이동, 참조와의 차이 |
| 바닥을 누른 채 수평으로 밀림 | 지지 발 미끄러짐 가능성 | 접촉 상태와 발 접촉면의 수평 속도 |
| 다리 목표는 움직이지만 실제 관절은 못 따라감 | 제어·effort·접촉 제약 가능성 | 목표–실제 관절 오차, 실제 effort |
| 몸은 이동하지만 그때 책을 놓침 | 잡기와 이동 부하의 결합 문제 | 손–책 상대 운동, 하중, 손가락 명령 |

단순히 보행 보상을 추가하거나 마찰을 높이기 전에 이 구분이 필요하다.

## 2. 지금 가능한 원인 가설

| 가설 | 이를 지지하는 상황 | 아직 필요한 증거 |
|---|---|---|
| **H1. 실제 pickup 이후 자세가 보행으로 연결되기 어렵다** | 참조 중간 시작은 부분 운반이 가능하지만 실제 경로에서는 웅크림 | 같은 참조 시점의 발·골반·책·history 비교 |
| **H2. 한쪽 팔로 멀리 든 책의 하중이 지지 전환을 어렵게 한다** | 왼팔을 뻗고 낮고 넓게 버티는 모습 | 책 하중만 줄였을 때 첫 발·몸 이동이 회복되는가 |
| **H3. 오른손을 떼는 시점이 실제 잡기 안정화보다 빠르다** | 시연의 한 손 전환을 따르지만 실제 접촉은 다를 수 있음 | 오른손 이탈·책 회전·첫 발 이동의 선후관계 |
| **H4. 발의 접촉·제어 자체가 이동을 막는다** | 목표와 실제 발 동작 차이 또는 미끄러짐이 있을 수 있음 | 발 접촉력·바닥 근접·속도·관절 추종 계측 |

**현재 H1은 기존 중간 시작 진단으로 뒷받침되지만, H2–H4는 직접 검증되지 않았다.** 한 손 하중이 문제라는 해석은 가능성이며 확정 원인이 아니다. [기존 중간 시작 진단][iteration]

## 3. 공통 준비 — 손과 발을 같이 측정하기

### 3.1 고정 조건

- 정책: fix-4 e3000, training seed 0.
- 물리·책 질량·보상·ATS·평가 모드를 기본 조건에서 유지한다.
- 기본 평가와 교란 평가는 섞지 않는다. 우선 기본 상태에서 원인을 분리한다.
- 참조 프레임과 reset 이후 제어 step `t`를 함께 저장한다. 기본 평가에서 참조 프레임은 `t+3`이다.
- 초기 기능 확인은 8개 환경으로 하고, 유효한 비교는 조건별 32개 환경 × 평가 seed 101·102·103을 권장한다.
- seed 반복은 같은 학습 정책의 평가 반복이다. 여러 학습 seed를 시험한 것으로 해석하지 않는다.

모든 새 조건을 한 번에 대규모로 실행하지 않는다. 먼저 계측과 개입이 실제로 작동하는지 짧게 확인한다.

### 3.2 최소 계측 목록

| 영역 | 저장할 값 | 판단 목적 |
|---|---|---|
| 발 | 양쪽 발목·앞발의 pose/velocity, net contact force | 들림·착지·지지·미끄러짐 구분 |
| 몸 | root/골반 pose와 속도, 다리 관절 목표·실제 상태 | 몸 이동과 관절 추종 확인 |
| 양손 | 손목 pose, 손가락 목표·실제 관절, 손끝 힘 | 오른손 이탈과 왼손 잡기 유지 확인 |
| 책 | pose/velocity, 실제 mass·COM·inertia, 손 기준 상대 자세 | 하중·회전·미끄러짐 확인 |
| 학습 입력 | phase, history 출처, 보상 항, 종료 판정 | 초기화·학습 조건의 차이 확인 |

**발 접촉 계측 시 주의**

- 실제 모델의 발 body는 `jLeftAnkle`, `jLeftBallFoot`, `jRightAnkle`, `jRightBallFoot`다. 발목만 보면 앞발 지지를 놓칠 수 있으므로 두 부분을 함께 본다.
- 기존 코드에 `left_foot/right_foot` 센서 생성 코드가 있으나, 실제 모델 이름과 다르며 force-sensor tensor 취득·refresh는 주석 처리돼 있다. **기존 발 센서가 정상 기록되고 있다고 가정하지 말고 런타임 body 이름·인덱스를 확인한다.** 이것이 현재 실패의 원인이라고 단정하는 것은 아니다.
- 우선 실제 body 이름으로 기존 net contact tensor를 매핑하고, 바닥 높이·자세와 함께 접촉을 추정한다. net force는 바닥 접촉쌍만의 힘이 아니므로 다른 접촉을 섞지 않도록 확인한다.

[발 모델][asset] · [기존 센서 코드][sensors] · [기존 rollout 기록][rollout]

### 3.3 이벤트를 이렇게 정의한다

- **발 들림/착지:** 바닥과의 거리·접촉력·지속 시간을 함께 사용한다. 임계값은 무접촉/정지 지지 구간의 노이즈와 참조 보행으로 정하고 모든 조건에 동일하게 적용한다.
- **발 미끄러짐:** 지지 중 바닥 가까운 접촉면 점의 수평 속도를 본다. 발목 중심의 속도만으로 판정하면 발의 회전을 미끄러짐으로 오인할 수 있다.
- **유효 보행:** 참조 이동 방향으로 몸이 진행하고, 참조에 맞는 발 지지 변화가 나타나는지 본다. 단순 발 움직임 수나 총 이동거리만으로 평가하지 않는다.
- **한 손 전환:** 손목이 멀어졌다는 조건만 쓰지 말고, 손–책 표면 근접·상대 운동·접촉력 변화를 함께 본다. 접촉쌍 정보가 없으면 ‘전환 추정 시점’으로 기록한다.
- **잡기 유지:** 책을 손 좌표계에서 추적한다. 손목 거리와 책 높이로 계산하는 기존 `held`는 보조 지표로 유지한다.

전신+책의 질량중심과 추정 지지 영역도 참고할 수 있다. 다만 동적 보행에서 질량중심 투영이 영역 안에 있는지만으로 안정/불안정을 확정하지 않는다. 접촉점이 없으면 계산한 지지 영역 역시 근사치다.

## 4. 실험 E1 — 발과 손의 실패 순서를 먼저 확인

**가장 먼저 수행할 실험이다. 재학습과 외부 보조는 없다.**

| 조건 | 시작 상태 | 비교 구간 |
|---|---|---|
| A: 실제 pickup 경로 | 참조 frame 2에서 정책이 직접 집기 | 보행 전환 전후 |
| B: 참조 운반 시작 | 같은 정책을 참조 frame 70 또는 85에서 초기화 | A와 같은 참조 프레임 구간 |

기존 중간 시작 probe의 요약값이 있으면 재사용하고, 부족한 발·손 상세 기록만 추가한다. 최대 60프레임과 남은 시연 길이 중 짧은 구간을 맞춰 비교한다. B는 history와 속도 등도 초기화하므로 단일 자세 요소의 효과로 해석하지 않는다. [기존 probe][starts]

**핵심 결과물은 한 장의 시간축이다.**

```text
오른손 이탈 → 왼손-책 상대 운동 → 골반/체중 이동 → 발 들림·착지 → 몸의 진행 → 낙하
```

화살표는 예상 순서가 아니라 **실제로 측정해서 정렬할 사건 목록**이다. 다음 질문에 답한다.

1. 책이 안정적인 동안에도 발을 못 떼는가?
2. 한 발이 들리거나 지지가 바뀐 직후 책이 돌아 나가는가?
3. 발은 움직이는데 착지가 제자리여서 몸이 안 가는가?
4. 오른손 이탈 직후, 첫 보행 이전부터 책의 회전·골반 하강이 시작되는가?
5. 참조 시작에서는 같은 문제가 사라지는가?

**E1만으로 결정할 수 있는 방향**

| 관찰 | 다음 우선순위 |
|---|---|
| 참조 시작은 걷고 실제 pickup 후만 멈춤 | 실제 pickup 상태를 포함하는 연결 학습 후보 |
| 책은 유지되지만 지지 전환에서 멈춤 | E2 하중 진단 |
| 오른손 이탈 뒤 곧바로 잡기가 무너짐 | E3 오른손 보조 진단 또는 정적 잡기 유지 진단 |
| 두 시작 조건 모두 발 미끄러짐·관절 추종 실패 | 발 접촉/제어의 해당 변수만 진단 |

## 5. 실험 E2 — 한 손 하중이 보행을 막는가

**목적:** 한 손으로 책을 버티는 부담을 줄였을 때 발의 지지 전환과 몸 이동이 회복되는지 본다.

### 5.1 조작할 변수: 책에 대한 부분 중력 보상

책의 질량·관성·형상은 그대로 두고, 책의 실제 질량중심에 위쪽 보조 힘을 적용하는 진단을 제안한다.

```text
보조 힘 = α × 책 질량 × 중력 크기
대조 조건 α = 0
진단 조건 α = 0.5  (제안값, 실행 전 고정)
```

이 기능은 **현재 실험 도구에 준비된 옵션이 아니며 추가 구현·검증이 필요하다.** 세계 좌표의 책 COM에 적용해 의도하지 않은 토크를 만들지 않고, 짧게 램프를 주어 갑작스러운 충격을 피한다. 제로 힘 조건에도 같은 코드 경로를 사용한다.

- 전역 중력을 바꾸면 사람과 발 접촉까지 바뀌므로 사용하지 않는다.
- 책을 손에 고정하거나 위치를 참조에 붙이지 않는다.
- 질량을 단순히 줄이는 방법은 관성도 바꿀 수 있어 이 실험과 같은 개입이 아니다.
- 이 결과는 보조가 있는 진단이며, 원래 과제의 성공률로 보고하지 않는다.

### 5.2 최소 비교

E1에서 문제가 나타나는 보행 전환 전 시점에 보조를 켠다. 사건 기반으로 켠다면 ‘책상 완전 분리 후 일정 시간’ 등의 규칙을 미리 고정하고, 규칙을 충족하지 못한 episode도 함께 보고한다.

| 시작 상태 | 보조 없음 | 책 하중 50% 보조 |
|---|---|---|
| 실제 pickup 경로 | A0 | A1 |
| 참조 운반 시작 | B0 | B1 — A 비교 해석에 필요할 때 추가 |

A0–A1 또는 B0–B1에서 바뀌는 것은 보조 힘뿐이다. 먼저 A0–A1을 비교하고, 실제 상태와 참조 상태의 상호작용을 확인할 필요가 있을 때 B를 추가한다.

### 5.3 결과 해석

| 결과 | 지지되는 설명 | 아직 단정할 수 없는 것 |
|---|---|---|
| 책 유지와 몸 이동이 함께 개선 | 책 하중이 잡기–보행 결합 문제에 기여 | 국소 손 접촉과 전신 균형 중 어느 쪽이 주원인인지 |
| 책은 더 오래 유지하지만 몸은 여전히 정지 | 하중은 잡기에 영향, 보행 연결은 별도 병목 | 보행 능력이 아예 없다는 결론 |
| 몸은 이동하지만 책 오차가 큼 | 이동 개시와 정확한 운반은 별개 | 원래 과제 해결 |
| 변화 없음 | 시험한 보조량에서 개선 근거 없음 | 하중이 전혀 중요하지 않음. 기존 정책의 분포 밖 개입일 수 있음 |

한 손 하중이 줄면 보행이 회복되는지를 보는 실험이지, ‘책이 1kg이라 너무 무겁다’를 미리 결론 내리는 실험이 아니다.

## 6. 실험 E3 — 오른손을 조금 더 유지하면 도움이 되는가

**목적:** 영구적인 양손 운반으로 바꾸기 전에, **한 손 전환 시점**이 병목인지 확인한다.

### 6.1 비교할 세 조건

| 조건 | 오른손 사용 | 질문 |
|---|---|---|
| R0: 원래 정책 | 정책이 원래대로 오른손을 뗌 | 기준 |
| R1: 전환 보조 | 첫 보행의 발 이동 후 새 지지가 확보될 때까지 오른손을 실제 접촉으로 보조하고 점진적으로 해제 | 잡기·보행 전환 구간만 보조하면 충분한가 |
| R2: 계속 보조 | 관찰 구간 동안 오른손 지지 유지 | R1으로 부족할 때 지속적인 양손 지지가 필요한가 |

R2는 R1의 결과 해석이 필요할 때만 추가한다. 보행이 시작되지 않아 R1이 무기한 유지되지 않도록 최대 보조 시간을 미리 정하고, 시간 초과를 실패로 별도 기록한다.

### 6.2 구현에서 지켜야 할 점

- 오른손의 관절 목표를 조절하는 별도 보조 제어가 필요하다. **손목을 책 근처로 보내는 것만으로 양손 지지가 만들어졌다고 판단하지 않는다.**
- 오른손이 책을 실제로 지지하는지, 책상·왼손·몸을 밀고 있지는 않은지 확인한다. 쌍별 힘이 없으면 주장 범위를 제한한다.
- 책을 손에 접착하거나 root를 고정하면 다른 실험이 된다. 보행 비교에서는 root를 자유롭게 둔다.
- 먼저 짧은 정지 조건에서 오른손 보조가 유효한 접촉을 만들고 비정상 관통·충격을 만들지 않는지 확인한다. 이 검증이 실패하면 ‘양손이 도움이 안 된다’고 해석하지 않는다.
- 왼손·다리의 정책은 유지하되, 오른팔 개입에 따른 상체·관측 변화는 필연적으로 발생한다. 따라서 결과는 **오른손 보조 전략 전체의 효과**이며, 하중 분배 하나만의 효과는 아니다.

이 실험과 E2를 처음부터 동시에 적용하지 않는다. E2는 하중을, E3는 오른손 지지와 전환 전략을 시험한다.

### 6.3 해석

- **R1만으로 보행이 개선되고 보조 해제 후에도 유지:** 한 손 전환 시점 또는 전환 상태 학습이 유력하다.
- **R2에서만 유지되고 해제하면 실패:** 지속적인 지지 또는 다른 잡기 구성이 필요할 가능성이 있다. 원래 한 손 과제는 아직 해결되지 않은 것이다.
- **책은 안정되지만 보행은 그대로:** 양손 강제보다 하체·실제 pickup 상태에서의 보행 연결을 우선한다.
- **몸의 시연 오차와 움직임이 악화:** 오른손을 계속 붙이는 목표가 원래 시연의 오른팔 동작과 충돌했을 수 있다.

**중요:** 원래 시연이 한 손 운반이므로 ‘양손 유지 보상’을 추가하면서 원래 오른팔 모방 목표를 그대로 두면 목표 충돌이 생길 수 있다. 진단 단계의 보조 결과와 정식 학습 목표를 분리해야 한다.

## 7. 진단 후 어떻게 다시 학습할까

### 기본 방향: 원래 한 손 과제의 재현을 유지

사용자가 과제 자체를 변경하지 않은 현재는 이 방향을 기본으로 둔다.

| 진단 결과 | 다음 학습 후보 | 최종 평가 |
|---|---|---|
| 실제 pickup 상태에서만 보행 실패 | 실제 pickup 종료 상태를 초기화 분포에 일부 포함하는 연결 학습 | 원래 frame 2, 외부 보조 없음 |
| E2에서만 보행이 회복 | 하중 보조를 단계적으로 0까지 줄이는 학습 후보 | 원래 1kg·원래 중력, 보조 힘 0 |
| R1에서 전환이 회복 | 오른손 보조를 점차 줄이거나 한 손 전환을 학습하는 후보 | 외부 오른손 제어 없음, 원래 과제 |
| 발 미끄러짐이 먼저 발생 | 확인된 발의 마찰·접촉 설정 하나 또는 미끄러짐 관련 학습 항 하나 | 책·손 물리와 ATS는 고정 |
| 다리 목표와 실제 움직임이 불일치 | 확인된 하체 PD/effort 문제 하나 | 다른 보상·초기화는 고정 |

보조를 줄이는 학습은 새 방법이다. 보조를 사용한 샘플 수와 제거 과정을 기록하고, **보조 없이 다시 평가할 때만 원래 과제 성능을 보고**한다. 초기화·보조·보상·solver를 한 번에 바꾸지 않는다.

### 대안: 양손 운반 자체를 새 목표로 삼는 경우

양손 운반이 연구 목적이라면 별도 변형 과제로 정의할 수 있다. 이 경우 양손 잡기 가능한 참조/목표, 오른팔 모방 항, 접촉 검증을 함께 설계해야 한다.

기존 10cm 물체 추종 지표도 병기할 수 있지만, **시연과 다른 양손 전략을 학습한 결과를 동일한 한 손 모방 baseline의 개선으로만 소개하면 안 된다.** 현재는 이 과제 변경을 결정한 상태가 아니다.

## 8. 무엇이 좋아져야 ‘개선’인가

| 평가 축 | 개선으로 볼 근거 | 착시 가능성 |
|---|---|---|
| 보행 | 참조 방향 몸 이동 증가, 실제 지지 전환, 낮은 지지 발 미끄러짐 | 발만 흔듦, 바닥에서 미끄러져 이동, 넘어지며 진행 |
| 잡기 | 이동 중 손–책 상대 운동 안정, 낙하 감소 | 정지 상태에서만 오래 유지, 외부 보조로 버팀 |
| 연결 | 직접 집기 후 보행 개시, 보조 제거 뒤에도 유지 | 참조 중간 시작에서만 성공 |
| 정확성 | 초기와 운반 구간 모두 물체 경로·타이밍 오차 감소 | lift 성공만 증가하고 첫 10cm 이탈은 더 빨라짐 |
| 전체 과제 | 고정된 기본/교란 프로토콜의 성공률 개선 | 바뀐 시연·보조 조건을 원래 과제와 혼합 |

지표는 조건별 분포와 평가 seed별 결과를 함께 보고한다. 단순 발걸음 수, 양손 거리, pelvis 높이만 보상으로 올리는 변경은 피한다. 제자리 발걸음·발 미끄러짐·책 가까이에 손만 두는 행동으로 수치를 높일 수 있기 때문이다.

정식 iteration은 기존 3,000 epoch·2,048 env·평가 조건별 96회 비교를 유지한다. 보조·새 초기화 등 추가 자원이 있다면 총 샘플 예산을 함께 기록한다. 이어 학습하는 경우에는 같은 checkpoint와 같은 추가 예산의 무변경 대조군을 둔다. [프로토콜][protocol]

## 9. 당장 실행할 범위

- [ ] fix-4 checkpoint·원시 trace·전체 영상을 확보한다.
- [ ] 실제 발 body 인덱스와 추가 계측을 검증한다.
- [ ] **E1부터** 수행해 한 손 전환, 지지 변화, 책 이탈의 순서를 확인한다.
- [ ] 책 하중이 지지 전환과 연관되면 E2를 수행한다.
- [ ] 오른손 이탈이 먼저 문제를 만들거나 E2만으로 구분이 안 되면 E3를 검토한다.
- [ ] 근거에 맞는 변경 하나를 고른 뒤 새 iteration의 가설·실패 기준을 적는다.
- [ ] 기존 행동 보존·reset/resume·설정 적용을 짧게 검증한 뒤 정식 학습한다.

E1 상세 계측, E2 하중 보조, E3 오른손 보조는 **추가 구현이 필요하며 실행 명령이 이미 준비된 기능이 아니다.** 기존 `policy_starts.py`는 참조 시작 요약 비교만 지원한다. 원본 checkpoint와 전체 영상은 Git 제외 파일이므로 실제 실행은 자료가 있는 학습 서버에서 해야 한다.

**최우선 결정은 “양손으로 바꿀까?”가 아니라 “책이 불안정해서 발을 못 옮기는가, 발을 못 옮겨 책을 놓치는가, 둘을 연결하는 상태가 잘못됐는가?”를 구분하는 것이다.**
