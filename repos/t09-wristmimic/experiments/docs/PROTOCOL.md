# T09 실험 프로토콜

과제 T09 Wrist-guided humanoid manipulation. Baseline은 과제 가이드(`3dv-project/README.md` 4절, `05_robotic_manipulation` T09)가 지정한 **WristMimic**이다.
이 문서는 **결과를 보기 전에** 정해 둔 규칙이다. 결과를 본 뒤 규칙을 바꾸면 그 사실과 이유를 이 문서 끝 "변경 기록"에 적는다.

작성일: 2026-10-04. 기준 코드: `repos/t09-wristmimic` (원본 commit `8e0178d` + `experiments/docs/CODE_NOTES.md` 1절의 로컬 수정).

### 1.1 손 모델 선택 (`s110_ROM.xml` vs `s110_intermimic_ROM.xml`)

두 XML은 관절 범위와 geom이 같고 **뼈 길이만 다르다**. 모션 데이터의 실제 뼈 길이(전 프레임 평균)와 비교했다.

| 구간 | 데이터 | `s110_ROM.xml` | `s110_intermimic_ROM.xml` |
|---|---|---|---|
| 팔꿈치→손목 | 0.2285 m | 0.2285 | 0.2370 (+3.7%) |
| 손목→검지1 | 0.1045 m | 0.1045 | 0.1100 (+5.3%) |
| 손목→엄지1 | 0.0546 m | 0.0546 | 0.0577 |
| 어깨→팔꿈치 | 0.2781 m | 0.2782 | 0.2782 |

`s110_intermimic_ROM.xml`을 쓰면 손목 위치 목표 자체에 약 1 cm의 체계적 오차가 생긴다. 우리 실험 변수가 손목 위치 임계값(0.035~0.14 m)이므로 이 오차는 결과를 오염시킨다. **데이터와 정확히 맞는 `s110_ROM.xml`로 고정**한다 (원본 `scripts/train_parahome.sh`도 이 파일을 쓴다. 원본 README 예시는 다른 파일을 쓴다).

## 3. 평가 규칙

1. **채점 기준 고정.** 테스트 모드의 "실패"에는 손목 reset 조건이 들어 있다. 학습 설정 그대로 채점하면 변형마다 채점 기준이 달라진다. 그래서 **모든 체크포인트를 `configs/env/eval_default.yaml`(기본 손목 임계값과 창) 하나로 평가**한다. 평가 설정의 sha1이 결과 json(`meta.eval_cfg_sha1`)에 기록된다.
2. **손목과 무관한 지표를 따로 보고**한다 (4.1의 과제 성공). `reset_off`처럼 손목 조건을 끈 변형은 공식 성공에서 구조적으로 불리할 수 있으므로, 주장은 과제 성공과 함께 한다.
3. **같은 예산.** 모든 비교는 같은 학습 epoch 수 T의 체크포인트로 한다 (5절). `report.sh <T>`가 epoch T 체크포인트가 없는 run을 표에서 빼고 경고한다.
4. **학습 장면 = 평가 장면.** 장면당 정책 1개이고 장면 하나만 쓴다. 일반화를 주장하지 않는다. 시뮬레이터 성공률을 실로봇 성공률이라고 하지 않는다.
5. **논문 재현이 아니다.** 1024 env, PhysX 버퍼 축소, 짧은 예산이다. "축소 설정 baseline"이라고 부르고, 논문 숫자와 섞어 쓰지 않는다.

### 3.1 평가 방식 두 가지

| 이름 | 설정 | 의미 |
|---|---|---|
| 결정적 (`det`) | 행동 = 정책 평균 μ, env 8개 | 공식 프로토콜(`run.py --test --test_no_reset`)과 같은 경로. env 8개는 **물리 잡음 반복** (4.3) |
| 확률적 (`stoch`) | 행동 = μ + N(0, σ²), σ = e^-2.9 ≈ 0.055 (학습 때와 같은 잡음), env 32개 | 행동 잡음에 대한 강건성. 성공률이 0/1이 아닌 비율로 나와 비교에 쓰기 좋다 |

두 방식 모두 한 에피소드 = 시퀀스 전체(프레임 1~154), 실패해도 reset하지 않고 끝까지 진행, 실패 플래그는 한 번 서면 유지된다.
평가기(`tools/evaluate.py`)는 원본 `run.py --test`와 같은 정책/환경 경로를 쓰며, 파이프라인 점검에서 원본 출력이 우리 분포 안에 있음을 확인했다 (README 2절).

## 4. 지표 정의

모든 지표는 `tools/metrics.py`에 구현되어 있다. 프레임 k는 k번째 제어 스텝(30 Hz) 후의 시뮬레이션 상태를 참조 프레임 k와 비교한다.

### 4.1 성공

| 지표 | 정의 |
|---|---|
| 공식 성공 `official_success` | 프레임 1~154 동안 termination 조건이 한 번도 서지 않음. 조건 = 넘어짐 ∨ kinematic(몸 ∨ 물체 ∨ 손목) ∨ 접촉. env의 `terminate` 플래그와 일치하는지 매번 검사한다 |
| 진행률 `progress` | 첫 실패 프레임 f에 대해 (f−1)/(T−1), 실패 없으면 1 |
| 과제 성공 `task_success` | **손목과 무관한 성공.** 모든 프레임에서 월드 좌표 물체 위치 오차 ≤ ε **그리고** 넘어지지 않음 |
| 과제 진행률 `task_progress` | 물체 오차 > ε 또는 넘어짐이 처음 생긴 프레임 기준, 정의는 진행률과 같음 |

### 4.2 사전에 고정한 상수 (결과를 보고 바꾸지 않는다)

| 상수 | 값 | 근거 |
|---|---|---|
| ε (과제 성공 물체 오차) | **0.10 m** | 주전자 크기(약 0.2 m)의 절반. 이보다 크게 벗어나면 "옮기기"를 했다고 보기 어렵다. env의 물체 termination(물체 점 평균 거리 0.5 m)은 너무 느슨해서 쓰지 않는다. 다른 ε로도 다시 계산할 수 있게 최대 오차를 저장한다 |
| 넘어짐 | 골반 높이 < 0.3 m | env 코드의 실제 termination 높이 (`_build_termination_heights`에 하드코딩. 설정 파일의 `terminationHeight: 0.15`는 쓰이지 않음) |
| 발 접촉 | 발 body 순 접촉력 > 1 N | 공중의 발(0 N)과 구분. 0.1 N(env의 접촉 판정값)은 잡음에 민감 |
| 관절 한계 근접 | 한계까지 0.035 rad (약 2°) 이내 | |

### 4.3 물리 잡음 (2026-10-04 확인)

같은 체크포인트를 결정적 행동으로 돌려도 **결과가 비트 단위로 같지 않다.** 프레임 6쯤부터 1e-5 m 수준의 차이가 생겨 커진다. 프로세스 사이에서도, 한 시뮬레이션 안의 env 사이에서도 그렇다 (GPU PhysX 연산 순서). 제안서 4절의 "평가가 결정적"이라는 가정은 틀렸다. 그래서:

- 결정적 평가도 env 8개(물리 반복 8회)로 하고 비율로 보고한다. 원본의 env 1개 결과는 이 분포의 표본 하나다.
- 분산의 원천은 (1) 학습 seed, (2) 물리 잡음, (3) 확률적 평가에서 행동 잡음 세 가지다. 주 결론은 seed 간 평균±표준편차로 낸다.

### 4.4 손목

| 지표 | 정의 |
|---|---|
| 손목 위치 오차 | ‖손목 위치 − 참조‖ (m). reset 조건이 쓰는 값과 같다 |
| 손목 회전 오차 | 손목 자세와 참조의 각도 차 (rad) |
| `*_window` | 손목 창(stage 1~3) 안의 평균. `*_mean`은 전체 프레임 평균 |
| `wrist_reset_frames` | 기본 임계값 기준 손목 reset 조건이 참인 프레임 수. 실패 후에도 계속 센다 (`test_no_reset`) |
| 집계 | 참조에서 접촉이 있는 손만 평균 (이 장면은 오른손) |

### 4.5 전신 안정성

| 지표 | 정의 |
|---|---|
| 넘어짐 `fell` | 골반 높이 < 0.3 m가 한 번이라도 있음 |
| 발 미끄러짐 `foot_slip_dist` | 발 body 4개(L/R Ankle, Toe)에 대해, 접지 중(> 1 N)인 프레임의 수평 속도 × dt 합 (m). 참조 동작에 걷기가 있으므로 절댓값보다 **변형 간 차이**로 본다 |
| 관절 한계 비율 `joint_limit_body` / `_hand` | 한계 근접 DoF 비율. 몸 63 DoF와 손가락 90 DoF를 나눈다 |
| 몸통 기울기 `torso_tilt_*` | `Torso` body의 국소 z축과 월드 z축의 각도. 참조 동작도 기울어 있으므로 **참조 대비 초과분** \|기울기 − 참조 기울기\|를 주로 본다 |
| 몸 추적 오차 `key_body_err_mean` | key body 21개 위치 오차 평균 (m) |

### 4.6 물체와 접촉

| 지표 | 정의 |
|---|---|
| 물체 위치/회전 오차 | **월드 좌표**에서 시뮬레이션 물체와 참조 물체의 차이. 에피소드 평균, 최대, 마지막 |

### 4.7 실패 원인

첫 실패 프레임에서 참이었던 조건을 모두 기록한다: `fall`, `body`(key body 최대 오차 > 0.35 m), `object`(물체 점 평균 오차 > 0.5 m), `wrist_L`/`wrist_R`(기본 임계값의 손목 reset 조건), `contact`(참조와 손 접촉 불일치가 10프레임 넘게 지속). 프레임마다 조건이 참인 횟수(`frames_*`)도 저장한다.

## 5. 학습 예산 T

### 5.1 실측 (2026-10-04, pipeline_check)

| 항목 | 값 |
|---|---|
| epoch당 시간 | 6.1~6.2 s (1024 env × horizon 32 = 32,768 env-step/epoch) |
| env-step/s | 약 5,800 |
| 최대 GPU 메모리 | 8.0~8.2 GB (데스크톱 약 0.5 GB 포함) |
| 1000 epoch | 약 1.7 시간 |

### 5.2 T를 정하는 규칙

Phase 1(기본 설정 seed 0, 6000 epoch, 약 10.3시간)의 모든 체크포인트(500 epoch 간격)를 평가해서:

1. **제안 T** = 확률적 평가의 과제 진행률을 체크포인트 3개 이동평균했을 때 최댓값의 95%에 처음 도달한 epoch. `report.sh`가 자동 계산한다.
2. **최종 T** = min(제안 T, 시간 예산이 허락하는 값), 500의 배수. 정한 값과 이유를 6절 변경 기록에 적는다.
3. 6000 epoch 안에 과제 진행률이 거의 오르지 않으면 (예: 0.5 미만에서 평평): 예비 장면 검토, 또는 이 사실 자체를 결과로 보고(축소 설정에서 학습 불가)하고 팀이 결정한다.

참고: 원본 스크립트에 남은 체크포인트 이름 `exp225_00043500`은 4만 epoch 이상(2048 env) 학습한 흔적이다. 우리 예산은 그보다 훨씬 작다. 이 차이를 발표에 명시한다.

## 6. seed와 가설 판정

- 1차: 모든 변형 seed 0. 기본 설정만 seed 0, 1, 2.
- 주장에 쓰는 변형(가설 판정 대상)은 seed 1, 2를 추가해 **seed 3개**로 판정한다 (`phase5_extra_seeds.sh`).
- **H1** (RQ1): stage 2 위치 임계값을 ×0.5 → ×2로 바꿀 때 공식 성공률 변화량 |Δ위치|가 회전 임계값의 |Δ회전|보다 크다. |Δ위치| ≤ |Δ회전|이면 기각. 보조: 과제 성공, 진행률. `REPORT.md` 7절이 Δ를 계산한다.
- **H2** (RQ2): gwp 70 → 30이면 발 미끄러짐·몸통 기울기 초과는 줄고(Δ<0) 물체 위치 오차는 커진다(Δ>0). 안정성이 개선되지 않거나 물체 오차가 커지지 않으면 기각. `REPORT.md` 8절.
- seed 3개 평균 차이가 seed 간 표준편차보다 작으면 "차이를 확인하지 못함"으로 보고한다 (부정 결과도 결과다).
